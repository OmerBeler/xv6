# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

xv6 is a re-implementation of Unix Version 6 for x86 multiprocessor systems, used as a teaching OS in MIT's 6.828 course. **Note:** This x86 version is no longer actively maintained; the current development is at the RISC-V port (https://github.com/mit-pdos/xv6-riscv.git).

## Build & Run

Requires the `i386-jos-elf-gcc` cross-compiler toolchain and QEMU.

```bash
make              # Build kernel and disk image
make qemu         # Run in QEMU with graphics (2 CPUs, 512 MB RAM)
make qemu-nox     # Run in QEMU without graphics (serial only)
make qemu-gdb     # Run QEMU with GDB stub on port 25000+
make clean        # Remove all generated files
```

Exit QEMU: `Ctrl+A` then `X`.

### Running tests (from within xv6 shell)

```
usertests    # Comprehensive system call test suite (30+ tests)
forktest     # Fork process limit stress test
stressfs     # Filesystem stress test
```

### GDB debugging

```bash
make qemu-gdb        # Terminal 1: start QEMU with GDB stub
gdb                  # Terminal 2: connects via .gdbinit (generated from .gdbinit.tmpl)
```

## Architecture

### Boot sequence (`main.c`)

`bootblock` → `entry.S` → `main()` initializes subsystems in order: memory allocator, kernel page table, multiprocessor, APIC, GDT, interrupts, console, UART, process table, buffer cache, file table, IDE, then boots other CPUs, creates the `init` process, and enters the scheduler loop.

### Kernel subsystems

| File(s) | Subsystem |
|---|---|
| `vm.c`, `kalloc.c`, `memlayout.h`, `mmu.h` | Virtual memory & paging; kernel mapped at 0x80000000 |
| `proc.c`, `proc.h`, `swtch.S` | Process table (64 max), round-robin scheduler, context switching |
| `trap.c`, `trapasm.S`, `vectors.pl` | IDT, 256 interrupt vectors; `vectors.S` is generated |
| `spinlock.c`, `sleeplock.c` | Spin locks (interrupt-disabling) and sleep locks (for I/O) |
| `fs.c`, `fs.h` | On-disk filesystem: boot|super|log|inodes|bitmap|data |
| `bio.c`, `log.c` | Buffer cache and write-ahead logging for crash recovery |
| `file.c`, `pipe.c` | File/pipe abstraction over inodes |
| `syscall.c`, `sysproc.c`, `sysfile.c` | 21 system calls |
| `ide.c`, `uart.c`, `console.c`, `kbd.c` | Device drivers |
| `mp.c`, `lapic.c`, `ioapic.c` | SMP: detects up to 8 CPUs, per-CPU LAPIC |

### System limits (`param.h`)

```c
NPROC = 64       // Max processes
NCPU  = 8        // Max CPUs
NOFILE = 16      // Open files per process
FSSIZE = 1000    // Filesystem blocks (512 bytes each)
LOGSIZE = 30     // Write-ahead log size
```

### Memory layout

- Physical: low memory (0–1 MB) for bootloader/real-mode; extended memory for kernel and processes
- Virtual: kernel mapped at 0x80000000 (high half); user processes grow upward from 0
- Max file size: 12 direct + 1 indirect block = 65,548 bytes

### System call flow

User code calls stub in `usys.S` → kernel trap → `syscall()` dispatches via table in `syscall.c` → `sysproc.c` or `sysfile.c` handler → return via trap frame.

### Filesystem layout

```
[Boot block | Superblock | Log (30 blocks) | Inode blocks | Free bitmap | Data blocks]
```

`mkfs.c` creates `fs.img` at build time. Logging in `log.c` wraps all FS mutations for crash safety.

## Key implementation details (from `TRICKS`)

- **fork() PID read**: Process PID must be read before marking RUNNABLE to prevent compiler reordering and process-reuse races.
- **pushcli()**: Always calls `cli()` first, then increments `ncli` — must not be reordered, or CPU tracking breaks during rescheduling.
- **Interrupt vectors**: `vectors.S` is auto-generated by `vectors.pl`; do not edit it directly.
- **Context switch**: `forkret` copies trap frame to `%esp` only on a process's first return to user space.

## User programs

`init.c` (PID 1) starts `sh.c` (the shell). Standard utilities: `cat`, `ls`, `grep`, `echo`, `wc`, `mkdir`, `rm`, `ln`, `kill`. User library in `ulib.c`/`umalloc.c`; syscall stubs in `usys.S`.
